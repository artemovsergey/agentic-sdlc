# Неделя 1. Практика: аудит окружения и постановка задачи

## Предусловия

- OpenCode установлен и запускается.
- Есть доступ к CollegeLMS и его `AGENTS.md`.
- Прочитан `lecture.md` этой недели.
- Открыт `results.md` — в него пишутся результаты шагов.

## Шаги

1. **Аудит окружения.** Выполните команды и запишите результат в таблицу `## Аудит окружения`:

   ```bash
   opencode --version
   opencode models
   opencode mcp list
   opencode plugin list
   opencode auth list
   ```

   Затем проверьте конфиг `~/.config/opencode/opencode.jsonc`, проектные `.opencode/skills` и `.opencode/agents`, а также `AGENTS.md` CollegeLMS. Заполните таблицу «компонент — что установлено — версия/путь — замечание». Отметьте, какие модели и агенты реально используются, какие MCP включены, какие skills доступны.

2. **Выбор задачи.** Возьмите одну низкорисковую задачу из `docs/spec/userstories.md` или из текущей работы. Задача должна касаться кода, тестов или документации. Не подходят: миграции БД, изменения `.env`, `docker-compose.yml` и GitHub Actions. Если подходящей задачи нет, сформулируйте учебную на небольшом изменении интерфейса или теста.

3. **Постановка.** Запишите в `## Постановка задачи` пять блоков: ожидаемое поведение, ограничения, неизвестности, 3–5 критериев приёмки, что вне рамок. Критерии должны быть проверяемыми: команда, наблюдаемое поведение, конкретное значение. Отдельно отметьте, какая команда из `AGENTS.md` подтвердит каждый критерий.

4. **Самодиагностика.** Оцените навыки 1–2 по вопросам из `course/roadmap.md`. Заполните `## Самодиагностика` в `results.md`. Обновите `course/roadmap.md` только если есть доказательство: артефакт, ссылка на коммит, запись в журнале.

5. **Проверка постановки.** Прочитайте постановку так, будто вы агент, который не видел проекта. Если хотя бы один блок требует уточнения — дополните. Проверьте, что в записи нет токенов, паролей и путей к секретам.

## Границы

- На этой неделе CollegeLMS не изменяется: только чтение и аудит.
- Не запускайте `opencode auth export`: команда печатает секреты в вывод. Для проверки провайдеров достаточно `opencode auth list`.
- Не меняйте глобальный конфиг и проектные настройки в рамках практики. Если правка нужна, запишите её как наблюдение и обсудите отдельно.

## Критерий готовности

Практика завершена, когда:

- таблица аудита заполнена и воспроизводима;
- постановку можно отдать агенту без дополнительных вопросов;
- каждый критерий приёмки проверяем и привязан к команде или наблюдаемому поведению;
- `results.md` заполнен, раздел `## Артефакт` содержит ссылку на постановку;
- в записях нет секретов.
