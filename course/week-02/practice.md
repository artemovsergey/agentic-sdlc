# Неделя 2. Практика: контекст-пакет и feedback loop

## Предусловия

- Заполнена постановка задачи из недели 1.
- Есть доступ к CollegeLMS и его `AGENTS.md`.
- Прочитан `lecture.md` этой недели.
- Открыт `results.md` — в него пишутся результаты шагов.

## Шаги

1. **Worktree.** Создайте отдельный worktree CollegeLMS вне прод-каталога и работайте только в нём:

   ```bash
   git -C /home/user1/CollegeLMS worktree add /home/user1/CollegeLMS-w02 -b feat/week-02-practice
   cd /home/user1/CollegeLMS-w02
   ```

   Проверьте, что вы в отдельном каталоге, а не в `/home/user1/CollegeLMS`. Прод-каталог не трогаем: там работают контейнеры.

2. **Контекст-пакет.** Под постановку недели 1 соберите в `## Контекст-пакет`: 3–7 файлов, которые участвуют в изменении; спеку или user story; ограничения из `AGENTS.md`; команды проверки; неизвестности. Для каждого файла — одна строка, зачем он нужен. Если файлов больше семи, объясните, почему без них не обойтись.

3. **Прогон проверок.** Передайте агенту контекст-пакет и постановку. Пусть он выполнит проверки по порядку и запишет в `## Журнал проверок` строку на каждую команду: команда, код возврата, краткий итог. Минимальный набор:

   ```bash
   dotnet build CollegeLMS.slnx
   dotnet csharpier check .
   dotnet test CollegeLMS.slnx --filter FullyQualifiedName~{Name}
   cd CollegeLMS.Next && npm run build
   cd CollegeLMS.Next && npm run check:design-system
   ```

   Если затронуто поведение в браузере, добавьте `cd CollegeLMS.Next && npx playwright test {spec}`. Полный прогон тестов не запускайте: он идёт в CI. Если команда недоступна или окружение не готово, запишите это как результат с причиной, а не пропускайте строку.

4. **Разбор вывода.** Для каждой упавшей команды найдите первую ошибку и запишите, что она означает: ошибка кода, ошибка проверки или проблема окружения. Не переписывайте тест под результат, пока не поняли причину.

5. **Пробелы `AGENTS.md`.** По итогам прогона найдите 1–3 пробела: чего не хватило агенту, чтобы действовать без вопросов. Для каждого запишите формулировку, которую стоит добавить, и обоснование. Не коммитьте и не применяйте правки: это решение автора проекта.

6. **Самодиагностика.** Оцените навыки 3–4 по вопросам из `course/roadmap.md`. Обновите `roadmap.md` только при наличии доказательства: контекст-пакет, журнал проверок, ссылка на коммит или запись в `results.md`.

## Границы

- Только отдельный worktree, не прод-каталог `/home/user1/CollegeLMS`.
- Не трогать миграции, `.env`, `docker-compose.yml` и workflow.
- Не коммитить, не мержить и не пушить в CollegeLMS: изменения остаются в ветке worktree.
- Не применять правки `AGENTS.md` самостоятельно: только предложения в `results.md`.

## Критерий готовности

Практика завершена, когда:

- контекст-пакет объясняет, зачем нужен каждый файл;
- журнал проверок воспроизводим: у каждой команды есть код возврата и итог;
- для каждой упавшей команды указана первая ошибка и её причина;
- предложения по `AGENTS.md` конкретны и обоснованы;
- `results.md` заполнен, раздел `## Артефакт` содержит ссылки на журнал и предложения.
